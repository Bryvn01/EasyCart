## MongoDB Atlas Setup

### 1. Create MongoDB Cluster

1. Go to https://www.mongodb.com/cloud/atlas
2. Sign up or log in
3. Create a new project: "EasyCart"
4. Click "Build a Database"
5. Choose **FREE** tier (M0 Sandbox)
6. Select region closest to Oregon (for Render compatibility)
7. Cluster name: `easycart-cluster`
8. Click "Create Cluster"

### 2. Configure Database Access

1. Go to "Database Access" in left sidebar
2. Click "Add New Database User"
3. Authentication Method: Password
4. Username: `easycart_user`
5. Password: Click "Autogenerate Secure Password" and **save it**
6. Database User Privileges: "Atlas admin"
7. Click "Add User"

### 3. Configure Network Access

1. Go to "Network Access" in left sidebar
2. Click "Add IP Address"
3. Click "Allow Access from Anywhere" (0.0.0.0/0)
   - This is required for Render to connect
4. Click "Confirm"

### 4. Get Connection String

1. Go to "Database" in left sidebar
2. Click "Connect" on your cluster
3. Choose "Connect your application"
4. Driver: Python, Version: 3.6 or later
5. Copy the connection string, it looks like:
   ```
   mongodb+srv://easycart_user:<password>@easycart-cluster.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
6. Replace `<password>` with the password you saved earlier
7. Add database name before the `?`:
   ```
   mongodb+srv://easycart_user:YOUR_PASSWORD@easycart-cluster.xxxxx.mongodb.net/easycart?retryWrites=true&w=majority
   ```

## Render Deployment

### Option 1: Automatic Deployment with render.yaml (Recommended)

1. **Push render.yaml to GitHub**
   ```bash
   git add render.yaml
   git commit -m "Add Render deployment configuration"
   git push origin main
   ```

2. **Connect to Render**
   - Go to https://dashboard.render.com
   - Click "New +" → "Blueprint"
   - Connect your GitHub account if not already connected
   - Select the `Bryvn01/EasyCart` repository
   - Render will automatically detect `render.yaml`
   - Click "Apply"

3. **Set Environment Variables**
   - After services are created, go to each service:

   **Backend Service:**
   - Navigate to "easycart-backend" service
   - Go to "Environment" tab
   - Add/Update these variables:
     ```
     MONGODB_URI=mongodb+srv://easycart_user:YOUR_PASSWORD@easycart-cluster.xxxxx.mongodb.net/easycart?retryWrites=true&w=majority
     SECRET_KEY=(auto-generated by Render)
     DEBUG=False
     ALLOWED_HOSTS=easycart-backend.onrender.com,.onrender.com
     CORS_ALLOWED_ORIGINS=https://easycart-frontend-zge5.onrender.com,https://easycart-admin.onrender.com
     ```

4. **Deploy**
   - Services will automatically deploy
   - Monitor deployment logs in each service's "Logs" tab
   - Wait for all services to show "Live" status

### Option 2: Manual Service Creation

If you prefer manual setup or render.yaml doesn't work:

#### Backend Service

1. Click "New +" → "Web Service"
2. Connect GitHub repository: `Bryvn01/EasyCart`
3. Configure:
   - **Name**: easycart-backend
   - **Region**: Oregon
   - **Branch**: main
   - **Root Directory**: backend
   - **Environment**: Python 3
   - **Build Command**:
     ```bash
     pip install -r requirements.txt && python manage.py collectstatic --no-input && python manage.py migrate --no-input
     ```
   - **Start Command**:
     ```bash
     gunicorn ecommerce.wsgi:application --bind 0.0.0.0:$PORT
     ```
4. Add environment variables (see above)
5. Click "Create Web Service"

#### Frontend Service

1. Click "New +" → "Static Site"
2. Connect GitHub repository: `Bryvn01/EasyCart`
3. Configure:
   - **Name**: easycart-frontend
   - **Branch**: main
   - **Root Directory**: frontend
   - **Build Command**: `npm install && npm run build`
   - **Publish Directory**: build
4. Add environment variable:
   ```
   REACT_APP_API_URL=https://easycart-backend.onrender.com/api
   ```
5. Click "Create Static Site"

**Note**: The frontend includes a `_redirects` file in the `public/` directory that ensures all routes are handled by React Router. This file contains:
```
/* /index.html 200
```
This is automatically copied to the build directory and tells Render to serve `index.html` for all routes, allowing client-side routing to work correctly.

#### Admin Dashboard Service

1. Click "New +" → "Static Site"
2. Connect GitHub repository: `Bryvn01/EasyCart`
3. Configure:
   - **Name**: easycart-admin
   - **Branch**: main
   - **Root Directory**: admin-dashboard
   - **Build Command**: `npm install && npm run build`
   - **Publish Directory**: build
4. Add environment variable:
   ```
   REACT_APP_API_URL=https://easycart-backend.onrender.com/api
   ```
5. Click "Create Static Site"

## Database Seeding

After backend is deployed successfully, seed the database with Kenyan products:

### 1. Access Backend Shell

**Option A: Using Render Shell (Recommended)**
1. Go to easycart-backend service in Render dashboard
2. Click "Shell" tab at the top
3. Wait for shell to connect
4. Run seeding command:
   ```bash
   python manage.py seed_products --clear
   ```

**Option B: Using Local Django with Production DB**
1. Set MONGODB_URI in local `.env` file to production connection string
2. Run locally:
   ```bash
   cd backend
   python manage.py seed_products --clear
   ```

### 2. Verify Seeding

After seeding completes, you should see:
```
Seeding Categories...
  ✓ Created category: Groceries
  ✓ Created category: Electronics
  ✓ Created category: Fashion
  ...
Seeding Products...
  ✓ Created: Unga wa Dola Maize Flour 2kg (KES 210, Stock: 150)
  ✓ Created: Safaricom Neon Ray Pro Smartphone (KES 8999, Stock: 35)
  ...
✓ Successfully seeded 50+ products in 10 categories
```

### 3. Test API

Visit: `https://easycart-backend.onrender.com/api/products/`

You should see JSON response with paginated products.

## Post-Deployment

### 1. Create Superuser

To access Django admin panel:

1. Access backend shell (see Database Seeding section)
2. Run:
   ```bash
   python manage.py createsuperuser
   ```
3. Follow prompts to create admin user
4. Access admin at: `https://easycart-backend.onrender.com/admin/`

### 2. Test Frontend

1. Visit: `https://easycart-frontend-zge5.onrender.com`
2. Verify products are displayed
3. Test:
   - Product search and filtering
   - Add to cart (requires login)
   - Category navigation

### 3. Test Admin Dashboard

1. Visit: `https://easycart-admin.onrender.com`
2. Login with admin credentials
3. Test:
   - View product list
   - Edit products
   - Delete products (creates event that updates frontend)

### 4. Verify Auto-Deploy

1. Make a small change to code
2. Push to GitHub main branch
3. Services should automatically redeploy
4. Monitor in Render dashboard

## Troubleshooting

### Backend Won't Start

**Issue**: Backend service fails to start

**Solutions**:
1. Check "Logs" tab for error messages
2. Verify MONGODB_URI is correct (common issue: wrong password)
3. Verify all required environment variables are set
4. Check MongoDB Atlas network access allows 0.0.0.0/0
5. Verify MongoDB cluster is active (not paused)

### Frontend Shows "No Products Yet"

**Issue**: Frontend displays empty state instead of products

**Solutions**:
1. Verify backend is running: Visit `https://easycart-backend.onrender.com/api/products/`
2. Check browser console for CORS errors
3. Verify `REACT_APP_API_URL` in frontend environment variables
4. Verify backend CORS_ALLOWED_ORIGINS includes frontend URL
5. Run database seeding if products don't exist

### CORS Errors

**Issue**: Browser console shows "blocked by CORS policy"

**Solutions**:
1. Verify backend CORS_ALLOWED_ORIGINS includes your frontend URLs
2. Make sure URLs are HTTPS in production
3. Check that django-cors-headers is installed
4. Verify CORS middleware is in settings.py MIDDLEWARE list

### Database Connection Issues

**Issue**: Backend can't connect to MongoDB

**Solutions**:
1. Verify MongoDB Atlas cluster is active
2. Check connection string format is correct
3. Verify password doesn't contain special characters that need URL encoding
4. Check MongoDB Atlas Network Access allows 0.0.0.0/0
5. Try connection from MongoDB Compass to test credentials

### Slow First Request (Cold Start)

**Issue**: First request after inactivity is very slow

**Explanation**: Render free tier has cold starts after 15 minutes of inactivity

**Solutions**:
1. Wait 30-60 seconds for initial request
2. Consider upgrading to paid plan for instant-on
3. Use external monitoring service to keep service warm

### Direct URL Access Shows "Page Not Found"

**Issue**: Visiting `/products` or other routes directly in the browser shows "Page Not Found" or returns a 404 error

**Explanation**: This is a common issue with Single Page Applications (SPAs) deployed on static hosting. When you visit a direct URL, the server tries to find a static file at that path instead of serving the React app.

**Solution**: The app includes a `_redirects` file that tells Render to serve `index.html` for all routes. This file is located in `frontend/public/_redirects` and contains:
```
/* /index.html 200
```

To verify this is working:
1. Check that `_redirects` exists in the build output: `frontend/build/_redirects`
2. Rebuild the frontend if necessary
3. Ensure the Publish Directory is set to `build` (not `frontend/build`)
4. Clear browser cache and try again

The app also includes a wildcard route (`*`) in `App.js` that displays a NotFound page for unmatched routes on the client side.

### Static Files Not Loading

**Issue**: CSS/JS files return 404 errors

**Frontend Solution**:
- Verify build command completed successfully
- Check "Publish Directory" is set to "build"
- Verify package.json has correct build script

**Backend Solution**:
- Verify collectstatic ran during build
- Check STATIC_ROOT and STATIC_URL settings
- For production, consider using S3 or CloudFront for static files

## Monitoring & Maintenance

### Health Checks

Render automatically monitors the `/api/health/` endpoint. If it returns non-200 status, Render will attempt to restart the service.

### Logs

View logs for each service in Render dashboard under "Logs" tab. Useful for debugging issues.

### Database Backups

MongoDB Atlas free tier includes point-in-time backups. Upgrade to M10+ for configurable backup schedules.

### Scaling

Free tier limitations:
- 750 hours/month shared across services
- Services sleep after 15 minutes of inactivity
- 512MB RAM per service

For production:
- Upgrade backend to Starter ($7/month) for 512MB always-on
- Upgrade to Standard ($25/month) for 2GB RAM and autoscaling
- Consider MongoDB Atlas M10 ($0.08/hour) for better performance
